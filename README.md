# Demand Driven Inflation

This repository contains the replication codes for Domenico Giannone and Giorgio E. Primiceri (2026), "Demand Driven Inflation", Brookings Papers on Economic Activity.

## 1. Software requirements

- **MATLAB.** The code was most recently run with **MATLAB R2025b** on a Mac, but it does not use any release-specific syntax and should run unmodified on other reasonably recent releases.
- **Statistics and Machine Learning Toolbox.** This is the only MATLAB toolbox the code depends on (it is used for `mvnrnd`, `gamrnd`, `ksdensity`, `prctile` and similar functions in the Bayesian VAR/DSGE estimation and posterior-summary code). No other toolbox is required.
- **Internet access** is needed only when running the `Get*Data.m` scripts described in Section 4; everything else (data preparation, estimation, figures, tables) runs entirely offline once the `.mat` files are in place.

No installation step is required beyond having MATLAB and the toolbox above; all other dependencies (third-party MATLAB packages) are vendored inside this repository — see Section 6.

## 2. Repository structure

The repository is split into four self-contained folders:

```
Descriptive/   Descriptive charts of the price components used throughout the paper
VAR/           Bayesian SVAR analysis (sign-restricted demand/supply decomposition)
DSGE/          DSGE estimation and decompositions
Realtime/      Real-time forecast-error analysis
```

Within each folder:

- **Main scripts** live at the folder's root: `Get*Data.m` / `Prepare*Data.m` (build the data), `Get*Draws.m` (run the Bayesian estimation), and `FigureN.m` / `TableN.m` (produce the paper's output).
- **`aux/`** holds this project's own helper functions specific to that topic (e.g. `LoadData.m`, `computeIRFs.m`, `fetchfile.m`, and, for VAR/Descriptive, `aux/lib/` with the data-fetching helpers such as `haverseries.m`, `blspanel.m`, `ecbseries.m`).
- **`data/`** holds the raw fetched series (`data/raw/haver/` or `data/raw/public/`, see Section 4) and the prepared `.mat` files the estimation/figure scripts actually load.
- **`results/`** is where each `FigureN.m`/`TableN.m` script saves its output (PDF figures, formatted tables).
- **`draws/`** (VAR and DSGE only) holds the saved posterior/prior draws from the Bayesian estimation — see Section 3 for why these are cached rather than regenerated by every figure.
- **Third-party packages** are vendored as siblings of `aux/`, not nested inside it, so their own internal structure stays intact: `VAR/GLP_PrePostCovid_ConstantCoeff/`, `DSGE/gensys/`, `DSGE/csminwel/`. See Section 6.

## 3. Reproducing the figures and tables

Run scripts from within their own folder (each folder's scripts use paths relative to itself). The general pattern in every folder is: build the data once, run the Bayesian draws once, then run each figure/table script, which only reads from `data/` and `draws/`.

**We cache posterior/prior draws to `draws/*.mat` instead of having each figure re-run the MCMC**, because the same set of draws is frequently reused by several figures/tables — re-estimating from scratch for every one of them would be needlessly expensive. Run the relevant `Get*Draws.m` script once; every figure/table below simply loads its `.mat` file.

### VAR

1. `GetVARData.m` → `PrepareVARData.m` → `data/VARData.mat` (see Section 4)
2. `GetSWfactor.m` → `PrepareSWfactor.m` → `data/SWcovid_quarterly.mat` (only needed for `Figure3.m`)
3. Draws (each reads `data/VARData.mat` via `aux/LoadData.m`):
   - `GetVARDraws.m` → `draws/PQus_draws.mat`, `draws/PQea_draws.mat` — used by `Figure2.m`, `Figure3.m`, `Figure12.m`
   - `GetVARDrawsHT.m` → `draws/PQHTus_draws.mat`, `draws/PQHTea_draws.mat` — used by `Figure5.m`, `Figure13.m`
   - `GetVARDrawsRF.m` → `draws/PQRFus_draws.mat`, `draws/PQRFea_draws.mat` — used by `Figure6.m`, `Figure14.m`
4. Run `Figure2.m`, `Figure3.m`, `Figure5.m`, `Figure6.m`, `Figure13.m`, `Figure14.m` — each loads the corresponding draws above and saves its PDF to `results/`.
5. `Figure11.m` and `Figure12.m` are self-contained: they run their own (smaller) posterior/prior estimation inline — `Figure12.m` also loads `draws/PQus_draws.mat` for its baseline shares — and save their own draws (`draws/AppendixSlopes_draws.mat`, `draws/AppendixShares_draws.mat`) as a byproduct, mainly so the exact draws behind the appendix figures are archived alongside the rest.

### DSGE

1. `GetDSGEData.m` → `PrepareDSGEData.m` → `data/DSGEData.mat`
2. `GetDSGEDraws.m` → `draws/DSGE_draws.mat` — used by `Figure8.m`, `Table1.m`, `Table2.m`
3. Run `Figure8.m`, `Table1.m`, `Table2.m`.

### Realtime

1. `GetRealTimeData.m` → `PrepareRealTimeData.m` → `data/CPIvintages.mat` and the real-time projections `.mat` file
2. Run `Figure9.m`, `Figure10.m`.

Realtime needs no API key: every source it uses (Philadelphia Fed, ALFRED, FRED, ECB/Eurostat) is free and public.

### Descriptive

1. Requires `VAR/data/VARData.mat` to already exist (see Section 2).
2. `GetChartData.m` → `PrepareChartData.m` → `data/DataChart.mat`
3. Run `Figure1.m`, `Figure4.m`.

## 4. Building the data from scratch

Every topic that fetches its own data splits that work into two scripts:

- **`Get*Data.m`** needs internet access. It fetches each raw series from its source and writes it, essentially unmodified, as a plain CSV under `data/raw/`.
- **`Prepare*Data.m`** needs no internet access. It reads those CSVs and performs all of the chain-linking, quarterly aggregation, seasonal adjustment and alignment needed to produce the final `.mat` file the estimation/figure scripts load.

The repository ships with the data already built from the authors' own source, **Haver Analytics**, so most users do not need to run these scripts at all. They matter to users who either want to regenerate the data or would prefer to use data from publicly provided sources.

`VAR/GetVARData.m` and `Descriptive/GetChartData.m` are the two scripts with a data source to choose (DSGE and Realtime draw only from free public sources — FRED, Philadelphia Fed, ECB/Eurostat — and need no key). Both expose the same switch near the top of the file:

```matlab
SOURCE = 'haver';   % 'public' or 'haver'
```

- **`SOURCE = 'haver'`** uses Haver Analytics and requires `HAVER_KEY` (set a few lines below the switch) to be a valid key; the script errors out if it is empty.
- **`SOURCE = 'public'`** uses only free public sources: the BLS public API for the US series, and DBnomics/ECB/Eurostat/FRED for everything else. A `BLS_KEY` variable is also provided just below the switch — supplying your own key (free registration at https://www.bls.gov/developers/) raises BLS's rate limits, but it is not required: if left empty, the script automatically falls back to BLS's own public, unregistered tier, which works with no key at all.

`Prepare*Data.m` has its own, independent copy of the same `SOURCE` switch, so fetching and preparing can be decoupled — for example, you can fetch both vintages at different times with `Get*Data.m` and only decide which one to build from later, by rerunning `Prepare*Data.m` with a different setting, with no internet access needed at that point. To switch the shipped data over to public sources, set `SOURCE = 'public'` in both `Get*Data.m` and the matching `Prepare*Data.m` and rerun both.

## 5. Known differences between the Haver and public EA data

The euro-area HICP series used in the VAR and descriptive charts are available both from Haver Analytics (the authors' source) and from free public sources (the ECB Data Portal). We compare the two vintages directly in `VAR/ComparePanels.m`, which reads both the `haver` and `public` raw vintages from `VAR/data/raw/` and `Descriptive/data/raw/` (so both `Get*Data.m` scripts must have been run once in each `SOURCE` mode) and writes a side-by-side comparison workbook, `VAR/data/HaverPublicComparison_EAEnergy.xlsx`, with one sheet per series (headline, ex-energy, goods, services, energy, household energy, transport energy).

Across all seven series, the mean absolute difference in year-over-year inflation between the two sources never exceeds 0.3 percentage points, and even the largest observed single-quarter discrepancy is under 1.2 percentage points (the two energy subcomponents that have no official seasonally-adjusted release in either source, and so require the same in-house seasonal adjustment regardless of vintage, show the largest — though still modest — wedge). Differences of this magnitude do not alter any of the paper's qualitative or quantitative conclusions. Users who switch the euro-area data to the public vintage can consult `VAR/ComparePanels.m` and its output workbook to see exactly where and by how much the two vintages diverge.

## 6. Third-party code

This repository vendors the following packages, unmodified beyond removing anything unrelated to the functions we call:

- **`VAR/GLP_PrePostCovid_ConstantCoeff/`** — the Minnesota-prior Bayesian VAR estimation package (`bvarGLP.m` and its subroutines) used to draw from the VAR posterior. It is not developed for this paper; please cite the original source if you use it:

  > Domenico Giannone, Michele Lenza and Giorgio E. Primiceri (2015), "Prior Selection for Vector Autoregressions", *The Review of Economics and Statistics*, 97(2), 436-451.

  (See the package's own `README.md` for further detail.)

- **`DSGE/gensys/`** — Christopher Sims' linear rational-expectations solver, used to solve the DSGE model at each candidate parameter vector. Please cite:

  > Christopher A. Sims (2002), "Solving Linear Rational Expectations Models", *Computational Economics*, 20(1-2), 1-20.

- **`DSGE/csminwel/`** — Christopher Sims' quasi-Newton optimizer, used to maximize the DSGE posterior.

All other code in this repository is original to this paper.
